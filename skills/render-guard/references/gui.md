# Desktop GUI editing

Read [GUI configuration and measurement](../../../engines/gui/GUARD.md) when setting up a project, selecting a measurement adapter or changing an explicitly requested window size.

- Preserve the user's requested elements, comparison controls and existing behavior. Visual work does not authorize feature, settings or history changes.
- For a configured project, use `render-guard gui begin --project <source-root> --scope <files...>`. For a new application, establish the smallest runnable screen before configuring its guard. Do not start substantial visual edits without a usable measurement adapter.
- Measure the correct running application before editing. Match it to the source project and runtime copy; record screen dimensions, DPI and state. Measure the requested and comparison controls' left, top, right, bottom, width, height and centers, then open the actual image.
- Distinguish outer input frames, inner editors, arrows, text and buttons. Preserve half-pixel differences. Center Y is `(top + bottom) / 2`; horizontal gap is the next control's left minus the previous control's right. Applied fonts and actual glyph pixels need separate evidence; a correct frame does not prove correct text.
- Batch cause-related changes. Use `render-guard gui scope` to change declared files. Do not restart begin to erase measurements, replace/delete/move entire existing GUI files, bypass hooks or unlock shared designs without user authorization.
- For compiled applications, synchronize the source and runtime copy, run `render-guard gui build`, and apply the newly built executable to the authorized runtime location. Follow the project's approved restart/settings procedure. For source-based applications, the adapter must identify the sources actually loaded by the running application.
- Run `render-guard gui after` with matching targets, dimensions, DPI, state and measurement tool. Run all project checks, including actual text, colors and changed display states. An explicitly requested window size change requires declared before/after dimensions and a matching, time-limited approval; it does not authorize changing DPI or state.
- Review `.gui-guard/comparison.json` and before/after images; configured regression screens check pixels outside allowed target regions. Inspect clipping, overlaps, duplicate borders, unequal gaps and color contrast. Preserve the user's chosen appearance.
- End with `render-guard gui verify`. Only the latest source/build/measurement/check receipt can pass. Installation, hook registration and successful compilation are not screen verification.
- Include `render-guard gui packet` output when delegating writable GUI work through supported Codex commands. Read-only calls pass through; use `<!-- render-guard: none -->` for non-visual work. Delegation does not bypass execution permissions.
- Keep measurement read-only. Preserve background monitoring, private settings and unrelated changes. Do not mix notification, sound or external-send tests into visual checks. Download-folder output and the Windows adapter's `-AllowDownloads` require the user's explicit request.

New Windows configurations can use Microsoft's WinApp CLI when targets can be uniquely identified. Preserve working Native Win32 and UIAutomation adapters and existing measurement conditions. Unsupported controls or fonts remain unverified; Qt/Tk, custom drawing and other OSes need a suitable project adapter. Pillow compares images; it does not measure GUI controls.
